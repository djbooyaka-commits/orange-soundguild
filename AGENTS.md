# Project Rules

- PC Remote uses a user-session agent, not a Windows secure-desktop service: fail closed for credential injection and secure-screen input; keep-awake must not disable sign-in or managed lock policies.
- PC live-adjacent controls live in a dedicated component and send the existing owner-scoped device command queue; the agent handles DPI before GUI imports and releases held mouse input when watching ends.
- PC agent self-updates through a detached helper that retries the file swap and always relaunches with a reset packager environment, because the running exe stays locked briefly and a onefile child must not reuse the parent's deleted temp folder.

- Subscription renewals reuse the existing verified payment handlers; a database insert trigger serializes same-user/tier payments and stacks paid time, and handlers return the stored expiration so all payment methods agree.
- The public Subscription page shows a sign-in prompt to visitors and reads subscription details only through authenticated user-scoped server functions.

- Last.fm curator passes are represented by a negative playlist adjustment, but removals must be clamped to the member's available balance so a pass never creates point debt.
- Last.fm room links share one room-level curator-named tab; each link is a row inside it, not another tab, so members can scan all links together.
- Curator Pool earnings use authenticated user-scoped reads of existing opt-ins and accounting; keep estimates separate from credited cashout balances because the summary does not accrue money.
- The Curator Playlists directory owns filtered options and selection for its submission form, using shared selection helpers so cards and the dropdown always target the same visible playlist.- Phone Remote: the Android app (android/) talks only to /api/public/remote/pair and /poll with a per-device token (server stores its sha256), so the phone never needs a site login; the web page sets watch_until so the phone streams frames only while viewed.
- Phone Remote live video uses WebRTC: the browser's offer travels as a webrtc_offer command and the phone's answer returns via /poll into remote_devices.webrtc_answer (non-trickle ICE, STUN only); taps go over the data channel when open, else fall back to queued commands, because the phone has no site login or realtime access.

- Android capture assistance must be bounded to a locally initiated capture request and a verified system capture dialog; stop on the activity result and locate confirmation controls afresh before gesture fallback to avoid touching unrelated prompts.
- Android updates use the fixed GitHub release's update.json, verify APK checksum/package/version/signature, and hand installation to Android via a cache-scoped FileProvider; this keeps phone credentials off GitHub and preserves user-confirmed installation.
- Android CI must reuse its signing certificate via configured signing secrets or the cached fallback key, and fail publication after cache loss rather than rotate an updater release's key; Android rejects differently signed updates.
- OSG Artists auto-remove reuses the team removal list and the OSG playlists' star setting, and counts meeting the minimum as a pass, so members shown as "Pass" never lose tracks.
- Spotify team and OSG Artists curator messages live in one server-only notice table keyed by room type and room id, read/written through membership-checked server functions, so members see the banner and only the room curator can edit it.
- Stream Tracker rooms resolve each member's Last.fm username through lastfm-room-account (room override in beta_room_lastfm_accounts; default lastfm_connections only for rooms with a Spotify/OSG playlist) for tracking, rescans and member cards, and every saved Last.fm username must be unused elsewhere on the site, so YouTube/Tidal/Apple Music plays never mix with another room's account.
- Remote devices sleep until Go live: /poll returns an idle_ms hint and rewrites last_seen only when stale (longer gap while idle), so the web online threshold must stay above idle interval plus that gap; this keeps idle phones/PCs from loading the database.
- Stream Tracker room submissions validate links against the selected playlist's platform via shared playlist-platforms helpers; non-Spotify tracks are stored under an ext: artist|title key so duplicate and hold checks keep working.
- Room playlist approvals for Orange Sound Guild playlists insert into the real on-site playlist (only when the room curator owns it), and YouTube, Apple Music and Tidal room playlists sync from their public pages/player APIs (YouTube's official API only if a YOUTUBE_API_KEY exists; Tidal falls back to its 50-song embed) with an empty result never wiping tracked songs; this keeps OSG/YouTube/Apple/Tidal rooms in step with their source playlists like Spotify ones.
- Track submissions (curator playlists, OSG Artists, Stream Tracker rooms, pool) auto-approve on submit through the same add-to-playlist helpers curators use, and a failed auto-approve leaves the row pending; this keeps one code path for adding tracks and never loses a paid submission.
